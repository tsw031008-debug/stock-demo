# 功能3“各种”业务分析

## 目标

分析试用期需求文档中的功能3“各种”。该功能不是一个通用查询，而是两个使用当天最新实时行情的股票预警接口：

1. 涨速预警。
2. 开板提醒。

本记录只明确业务范围、数据来源、计算口径、接口建议、边界和待确认问题，不直接实现代码。

## 已确认口径

- 两日涨幅使用`T-1`收盘价，三日涨幅使用`T-2`收盘价。
- 两个接口共享60秒全市场实时行情快照。
- 非交易日调用时返回业务提示“当前为非交易日”。
- 交易日非交易时段调用时返回业务提示“当前不在交易时间”。
- 涨速预警按当前实时日涨幅倒序，涨幅相同时按斜率差倒序，再按股票代码升序。
- 开板提醒按文档当前条件筛选涨停封板候选，不实现真正的盘中开板状态变化。
- “卖一为0”使用卖一量为0判断，卖一量只参与后端筛选，不对外返回。
- 涨速预警返回股票代码、名称、当前价格和当前涨幅。
- 开板提醒返回股票代码、名称、当前价格、当前涨幅和成交额亿元值。

## 一、需求原文整理

### 1. 涨速预警

- 获取当前最新且符合涨速条件的个股。
- 条件：三日斜率超过两日斜率。
- N日涨幅：`(某日价格 / 某日前N日价格 - 1) × 100%`。
- 两日斜率：两日涨幅除以2。
- 三日斜率：三日涨幅除以3。
- 两日范围又解释为“今日和上一个交易日”。
- 符合条件的股票按“涨幅”从大到小返回。

### 2. 开板提醒

- 获取当前涨停个股。
- 文档给出的筛选条件为：卖一为0、成交额大于0、当前价格大于0、名称不以`ST`或`*ST`开头。

### 3. 共同要求

- 两个接口都查询当天最新实时数据。
- 日期均使用交易日口径，不使用自然日替代交易日。
- 股票范围推荐复用当天沪深京A股完整清单；如果功能3只要求沪深A股，需要在编码前另行限定。

## 二、现有能力盘点

### 可直接复用

- `TradeCalendarService`：判断交易日并查询前第N个交易日。
- `stock_basic`：提供当天沪深京A股股票代码和名称清单。
- `stock_daily_quote`：已有近两年日行情，可提供历史收盘价。
- 腾讯全市场批量行情适配器：每批最多200只，已经支持市场前缀、限频、超时、有限重试和响应完整性校验。
- 腾讯当前行情已经解析：当前价、昨收价、成交额、卖一价、卖一量、涨跌幅和行情时间。

### 尚未具备

- 涨速预警和开板提醒的Controller、Service、DTO、VO及计算组件。
- 按指定历史交易日批量读取股票代码、交易日和收盘价的Mapper查询。
- 全市场实时行情在两个接口之间的共享机制。
- 功能3专用的计算和接口测试。

## 三、涨速预警业务分析

### 推荐的日期区间解释

需求同时出现两种表述：

1. N日涨幅使用`T-N`价格。
2. “两日就是今日和上一个交易日”。

两者原本存在冲突，现已确认采用更具体的第二种解释：

```text
两日涨幅 = (P(T) / P(T-1) - 1) × 100%
两日斜率 = 两日涨幅 / 2

三日涨幅 = (P(T) / P(T-2) - 1) × 100%
三日斜率 = 三日涨幅 / 3

涨速条件 = 三日斜率 > 两日斜率
```

其中`P(T)`使用腾讯当天最新当前价，`P(T-1)`和`P(T-2)`使用数据库对应历史交易日的收盘价。

示例：

```text
P(T)   = 12
P(T-1) = 11
P(T-2) = 10

两日涨幅 = 9.09%，两日斜率 = 4.55
三日涨幅 = 20.00%，三日斜率 = 6.67
6.67 > 4.55，股票进入涨速预警列表
```

### 排序字段

“按涨幅大到小”没有说明是哪一个涨幅，可能是：

- 当前实时日涨幅。
- 两日涨幅。
- 三日涨幅。
- 三日斜率与两日斜率的差值。

推荐按当前实时日涨幅倒序，因为该字段最能体现当前时刻的强弱，也与文档“按涨幅大到小”的通常含义一致；当前涨幅相同时，再按`三日斜率-两日斜率`倒序，最后按股票代码升序保证结果稳定。

### 推荐响应字段

- 股票代码。
- 股票名称。
- 当前价格。
- 当前涨幅。

接口只返回符合涨速条件的个股及必要展示字段。两日/三日涨幅和斜率只用于后端计算、筛选和排序，不返回给前端，也不直接返回数据库实体。

建议使用`pageNum`和`pageSize`分页，默认每页20条，单页最大100条。必须先对全量实时行情完成计算、筛选和排序，再截取当前页，不能先分页股票再计算。

响应精度建议：当前价格、当前涨幅、两日/三日涨幅和斜率均保留2位小数；计算过程保留8位并只在响应转换时舍入。

## 四、开板提醒业务分析

### 名称和条件存在矛盾

功能名称是“开板提醒”，但文档条件实际筛选的是“当前卖一为空的涨停股票”，更接近封板或涨停池，并不能判断股票曾经封板后又打开。

真正的“开板”通常需要比较盘中前后状态或最高价、当前价和涨停价；文档没有给出该算法。本阶段不应自行补充不同板块涨停幅度、价格精度或历史状态规则。

推荐最小实现严格采用文档条件，并保留接口业务名称“开板提醒”。该结果实际是“当前涨停封板候选”，不实现真正的盘中开板状态变化。

### 推荐字段映射

```text
卖一为0       -> ask1VolumeHand == 0
成交额大于0   -> turnoverAmountYuan > 0
当前价格大于0 -> closePrice > 0
排除ST        -> 股票名称不以ST或*ST开头
```

交易软件盘口中的“卖一”同时包含价格和挂单量；判断当前是否没有卖单时，卖一量为0比卖一价为0更直接。因此业务筛选使用`ask1VolumeHand == 0`，卖一价只用于行情一致性校验，不能把空值当成0。

### 推荐响应字段

- 股票代码。
- 股票名称。
- 当前价格。
- 当前涨幅。
- 成交额，单位亿元。

开板提醒的排序规则原文未定义，推荐按当前涨幅倒序，当前涨幅相同时按成交额倒序，再按股票代码升序。

卖一量只用于后端判断，命中结果中必然为0，没有展示价值，不返回给前端。建议同样使用`pageNum`和`pageSize`分页，默认20条、最大100条。当前价格、当前涨幅和成交额亿元值保留2位小数。

## 五、推荐数据流

1. 使用上海时区取得当前日期和时间。
2. 校验当前日期为交易日，并确定是否允许在非盘中时段查询。
3. 分页读取当天股票基础信息，确认数量达到完整性阈值。
4. 调用腾讯批量行情，每批最多200只，获得全市场实时行情快照。
5. 开板提醒直接基于实时行情字段筛选。
6. 涨速预警通过交易日历取得`T-1`、`T-2`，Mapper只查询股票代码、交易日和收盘价原始数据。
7. Service完成按股票组织数据，独立计算组件计算涨幅、斜率、筛选和排序。
8. Controller只完成响应转换和统一响应封装。

不需要新增业务数据表或Flyway脚本。功能3是实时查询，最小范围内不持久化预警结果。

## 六、接口建议

建议在`stockalert`模块下提供两个无参接口：

```text
GET /api/stockAlert/speed
GET /api/stockAlert/openBoard
```

两个接口都返回列表。是否分页取决于实际命中数量；根据项目规范，对外列表原则上应分页并限制最大页大小。如果前端要求一次获得全部预警股票，需要明确将预警结果视为有严格上限的小列表。

## 七、性能和实时性

当前股票数量约5547只，腾讯每批最多200只，完成一次全市场行情需要约28个批次。按当前1秒最小请求间隔，单次完整采集理论下限约27秒。

如果两个接口分别实时请求，会重复执行约56个批次，接口耗时和数据源压力都不可接受。可选方案：

1. 已确认：两个接口共享60秒实时行情快照；同一时刻只允许一个线程刷新。
2. 提供一个聚合接口，一次返回涨速和开板两组结果，只请求一次腾讯。
3. 每个接口独立实时请求，不增加缓存，但响应时间可能超过30秒，不推荐。

短时快照是本功能稳定使用的必要设计。第一阶段单体应用可采用进程内快照和刷新锁，不需要立即引入Redis或定时任务；刷新失败时不得用过期快照伪装最新数据。

## 八、异常和边界

- 非交易日返回业务错误，提示“当前为非交易日”。
- 交易日的开盘前、午休和收盘后属于“非交易时段”，不能提示“当前为非交易日”；推荐返回业务错误并提示“当前不在交易时间”。
- 当天9:10股票清单尚未同步完成时不得发起全市场实时请求。
- 腾讯返回股票数量不完整时整次刷新失败，不使用残缺快照替代完整数据。
- 新股缺少`T-1`或`T-2`历史收盘价时，不参与涨速计算，并应记录跳过数量。
- 当前价或历史收盘价为空、等于0时不计算涨幅，防止除零。
- 斜率相等不命中，必须严格大于。
- 金额、价格、涨幅和斜率统一使用`BigDecimal`。
- ST过滤按名称前缀执行，不扩大为名称任意位置包含ST，除非另行确认。

## 九、测试范围

### 涨速计算单元测试

- 三日斜率大于、等于和小于两日斜率。
- 跨周末、节假日、跨月和跨年取历史交易日。
- 当前价或历史价为空、为0。
- 新股历史数据不足。
- 多只股票筛选和排序稳定性。
- `BigDecimal`精度和最终小数位。

### 开板筛选单元测试

- 卖一为0且其他条件满足。
- 卖一不为0。
- 成交额或当前价为0。
- `ST`、`*ST`前缀过滤。
- 必要行情字段为空。

### 其他测试

- 腾讯固定样本解析，不在测试中调用真实网站。
- 历史收盘价Mapper集成测试。
- 两个Controller的参数、分页和响应字段测试。
- 共享快照的并发刷新、过期和失败回退测试（如果确认使用短时快照）。
