# 历史资金流向浏览器会话预热

## 状态

全量回补运行中。

## 问题定位

- 用户在浏览器直接访问万科A历史资金流向接口，成功返回 `rc=0` 和120条历史记录。
- Python `requests` 和Windows `curl` 直接访问同一地址时，东方财富会主动断开连接。
- Python先访问对应个股资金流向页面，再等待1.5秒请求历史JSON接口后，可以正常返回数据。
- 一次性预热不足以覆盖后续所有股票，因此调整为每只未缓存股票、每次重试前均访问对应个股页面。

## 实现口径

- 保持单线程，不采用并发请求。
- 每次HTTP请求之间至少间隔1.5秒。
- 普通网络异常最多重试2次，按60秒、120秒退避。
- HTTP 403或429立即停止。
- 成功JSON继续按股票代码缓存，任务中断后从缓存续跑。
- 已有 `EAST_MONEY` 正式数据继续受到幂等更新规则保护。
- 请求会话不读取系统代理，也不读取用户浏览器Cookie或登录数据。

## 验证结果

- 前3只受控运行成功落库，历史记录由120条增加到358条。
- 此前连续3次失败的 `000016` 使用对应股票预热后首次请求成功。
- 前11只受控运行累计幂等写入1315条。
- Python固定样本测试增加至6个，全部通过。
