# 功能12热门潜力科技股业务分析

## 需求原文整理

功能12的科技股候选池以内部板块接口 `GET /exponent/manage/plate/getStockByPlateId?plateId=676` 返回的全部股票代码为准，先排除股票名称包含 `ST` 或 `*ST` 的股票，再生成热门科技股和潜力科技股两组前五名。

热门科技股规则：

- 计算统计日相对前第20个交易日的20日涨幅。
- 按20日涨幅从高到低选取前5名。

潜力科技股规则：

- 15日涨幅小于15%。
- 10日涨幅大于1%。
- 5日涨幅大于0。
- 20日涨幅大于5%。
- 60日涨幅大于0。
- 成交额大于1亿元。
- 满足全部条件后，按统计日当日涨幅的绝对值从高到低选取前5名。

文档中的全部日期均指交易日，N日涨幅统一使用 `(统计日价格 / 前第N个交易日价格 - 1) * 100%`。

## 已确认候选池接口

- 接口地址：`http://test46.szdjct.com/exponent/manage/plate/getStockByPlateId?plateId=676`。
- 2026-09-08实测响应为HTTP 200，JSON结构为 `{"code": 200, "data": ["000004", ...]}`。
- `data` 是不带市场前缀的6位股票代码字符串数组，不包含股票名称或其他板块字段。
- 本次实测返回1943个代码，去重后仍为1943个；候选池不再从本项目 `THS_GN_3_LEVEL` 板块或功能8自定义 `TECHNOLOGY` 大类推导。

## 已有数据基础

- `stock_daily_quote` 已保存近两年股票日线，包含股票名称、收盘价、当日涨幅和成交额，能够覆盖最大60个交易日回看窗口。
- `TradeCalendarService` 已支持前第N个交易日查询，不能用自然日减法替代。
- 历史日线使用未复权收盘价；功能12在没有新口径确认前应继续沿用，不能自行切换复权方式。

## 推荐业务流程

1. 使用股票日行情表的最新日期作为统计日T，复用 selectLatestTradeDate()；不设置行情数量门槛，不因数量不足回退日期。表为空时明确报错。
2. 从交易日历取得T-5、T-10、T-15、T-20和T-60，不使用自然日减法。
3. 调用 `plateId=676` 接口取得股票代码数组；接口业务码非200、`data` 为空或代码格式非法时终止计算，重复代码按首次出现顺序去重。
4. 使用全部候选代码和 `[T, T-5, T-10, T-15, T-20, T-60]` 六个日期，一次批量查询股票日线；最多约返回 `1943 × 6` 条记录，不读取连续61天数据，也不逐股票查询。
5. 在Java中按股票代码和交易日组装行情。统计日T记录提供股票名称、当前收盘价、当日涨幅和当日成交额，5个历史基准日记录提供涨幅计算所需的基准收盘价；接口只返回代码，股票名称必须以T日日行情为准。
6. 建立两层过滤：共同候选先排除没有T日日线、名称包含 `ST`、当前收盘价为空或非正数的股票；潜力榜再额外排除当日成交额为空或不大于1亿元的股票。成交额条件不能提前作用于热门榜。
7. 在独立计算组件中分别计算热门和潜力名单：热门榜按20日涨幅降序，潜力榜按统计日当日涨幅绝对值降序，固定返回最多5只，并使用股票代码作为同值时的稳定排序条件。

## 计算口径

所有基准收盘价必须大于0。由于基准价为正数，筛选条件可以直接比较价格，避免除法和中间舍入：

- 15日涨幅小于15%：`currentClose < close15 × 1.15`。
- 10日涨幅大于1%：`currentClose > close10 × 1.01`。
- 5日涨幅大于0：`currentClose > close5`。
- 20日涨幅大于5%：`currentClose > close20 × 1.05`。
- 60日涨幅大于0：`currentClose > close60`。
- 成交额大于1亿元：`turnoverAmountYuan > 100000000`。

文档使用的均为严格大于或严格小于，因此恰好等于阈值时不入选。热门榜按未舍入的20日涨幅降序排列，潜力榜按统计日日行情中的当日涨幅绝对值降序排列；展示时如需返回涨幅再统一保留2位小数。

## 缺失数据处理

- 候选池接口调用失败、业务码非200或没有返回有效代码时直接报错，不返回空榜冒充真实结果。
- 统计日期查询不判断全市场行情完整性，数据齐全由上游采集流程保障。
- 候选池中没有T日日线的个股从共同候选中排除，缺失记录不能填零参与计算。
- 热门榜缺少T-20价格的股票不能计算20日涨幅，只从热门榜排除。
- 潜力榜缺少任一T-5、T-10、T-15、T-20或T-60价格时不能判断全部条件，只从潜力榜排除。
- 新上市不足60个交易日的股票仍可参加热门榜，但不能参加潜力榜。

## 接口和分层建议

功能12属于股票预警和筛选结果，建议放入现有 `stockalert` 模块：

```text
GET /api/stockAlert/technologyStocks
```

推荐响应包含统计日期和两组列表：

```json
{
  "statisticsDate": "2026-09-08",
  "hotStocks": [
    {
      "rank": 1,
      "stockCode": "000001",
      "stockName": "示例股票"
    }
  ],
  "potentialStocks": []
}
```

最小展示字段与示例图一致，为排名和名称；建议同时返回股票代码作为稳定唯一标识。未确认前不额外返回全部指标明细。

建议在 `stockalert` 模块新增独立候选池数据源适配器、计算组件和查询Service；Controller只完成响应转换。候选池接口地址应通过配置提供，`plateId=676` 作为明确业务标识集中管理，禁止在多处散落硬编码。外部请求设置连接和读取超时，在数据库事务外完成，并校验业务码、数组和股票代码格式。Mapper XML使用候选代码集合和6个目标交易日一次批量查询原始行情字段，所有涨幅、筛选和排名均在Java中完成，禁止逐股票查询。

## 无需新增的内容

- 当前需求只展示最新一期前五名，不需要新增结果表。
- 不需要新增定时任务，查询时使用最新落库日期的日线动态计算即可。
- 暂不需要Redis缓存；每次查询通过指定候选池接口取得最新代码集合。
- 如果后续明确要求保存每日榜单、按历史日期查询或主动推送预警，再单独设计结果表和15:15盘后任务。

## 已确认补充口径

1. 热门榜和潜力榜相互独立，允许同一只股票同时进入两组。

## 测试重点

- 热门榜20日涨幅排序、恰好5%及同涨幅稳定排序。
- 潜力榜六个严格条件的边界值，每次只让一个条件不满足。
- ST和`*ST`名称过滤。
- 使用最新入库日期且不执行数量检查；无日线数据时报错，单只候选缺少T日日线时只排除该股票。
- 成交额不大于1亿元时只排除潜力榜候选，不影响热门榜候选。
- 不足60日新股只参加热门榜。
- 缺少统计日或历史基准价、价格非正数、成交额为空等异常。
- 交易日跨周末、节假日、跨月和跨年。
- 候选池接口正常响应、重复代码去重、非200业务码、空数组、非法代码和请求超时。
- Mapper批量查询、Controller两组前五名和日期格式。

## 验收标准

- 基准股票范围与 `plateId=676` 接口返回值一致，ST股票全部排除。
- 热门科技股严格按20日涨幅选取前5名。
- 潜力科技股使用统计日T的当日成交额执行严格大于1亿元判断，同时满足其余阈值后，按统计日当日涨幅绝对值选取前5名。
- 热门榜与潜力榜允许出现同一只股票，不做互斥排除。
- 所有N日偏移均使用交易日历，金额单位统一为元。
- 候选池接口地址可配置，查询不产生N+1 SQL，数据不完整时不返回伪造结果。
