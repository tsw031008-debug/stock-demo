# 功能5“板块涨停个数”业务分析

## 状态

业务分析完成，并已按推荐口径进入实现。具体实现结果见
`2026-08-26-033-plate-limit-up-implementation.md`。

## 文档要求

- 从指定板块接口获取所有板块以及每个板块包含的股票，并保存板块与成分股关系。
- 在记录股票日线的同时记录板块日线。
- 板块年初首个交易日的 `open` 为1000；后续交易日的 `open` 等于上一交易日的 `close`。
- 板块 `close = open × (1 + 板块涨幅 / 100)`。
- 板块涨幅为成分股涨幅的算术平均值。
- 板块成交额为成分股成交额之和。
- 查询当天最新数据，返回板块名、总个数、板块涨幅、涨停个股数和涨停个数占比。

## 板块来源核验

2026-08-26对文档指定地址进行了一次只读请求：

```text
GET http://test46.szdjct.com/exponent/manage/plate/getThsgn3LevelPlate
```

- HTTP状态为200，响应为JSON，响应体约440 KB。
- 顶层结构为 `{"code": 200, "data": {...}}`。
- `data` 是“板块名称 -> 股票代码数组”的对象，例如 `长三角一体化-概 -> [600018, ...]`。
- 响应没有板块ID、股票名称、数据日期或版本号，板块名称只能作为当前来源下的业务标识。
- 接口名称及实测板块名表明它返回同花顺三级概念板块，不能直接表述为覆盖行业、地域等全部类别的“所有板块”。
- 同一股票可以属于多个板块，板块与股票必须按多对多关系保存；同一板块内的重复代码需去重。

## 现有能力

- `stock_basic` 已保存股票代码、名称和当天有效股票清单。
- 腾讯实时行情已经包含当前价、涨跌幅、成交额和卖一量。
- 股票日行情表已经包含板块日线计算需要的 `change_percent` 和 `turnover_amount_yuan`。
- 股票预警已经实现60秒全市场实时行情快照和文档口径的涨停候选判断。
- 当前没有板块、板块成分股和板块日线表，也没有 `plate` 业务模块。
- 股票预警的实时快照目前是其Service私有实现，板块功能若另建快照会重复请求腾讯全市场行情。

## 推荐业务口径

### 1. 板块范围

当前阶段仅实现指定接口返回的同花顺三级概念板块。数据库保存接口原始板块名称，包括名称中的 `-概` 后缀，不自行删除或合并名称。

### 2. 有效成分股

- 原始成分关系按接口完整保存。
- 当天计算时使用“板块成分股与当天 `stock_basic` 股票清单的交集”，避免退市代码或来源中的失效代码进入分母。
- `totalStockCount` 表示当天有效成分股数量。
- ST股票仍属于板块并计入总个数，只是不计入文档定义的涨停个股数。

### 3. 板块涨幅和成交额

```text
板块涨幅 = 有有效涨跌幅的成分股涨跌幅之和 / 有效成分股数量
板块成交额 = 有效成分股成交额之和
```

- 使用简单算术平均，不按市值或成交额加权。
- 成交额数据库统一保存为元，接口如后续展示成交额再转换为亿元。
- 空涨跌幅和空成交额不能当作0；全市场行情快照不完整时整次查询失败，避免静默计算残缺板块。
- 停牌股票若数据源明确返回涨跌幅0，可正常参与平均值。

### 4. 涨停个股数

为了与功能3保持一致，推荐复用已经确认的文档条件：

```text
卖一量 = 0
成交额 > 0
当前价格 > 0
股票名称不以 ST 或 *ST 开头
```

该条件实际是“当前无卖一挂单的涨停候选”，没有校验不同市场和股票类型的10%、20%、30%涨停价格。本阶段不额外引入另一套涨停算法，否则功能3与功能5会出现同一只股票判断不一致。

```text
涨停个数占比 = 涨停个股数 / 当天有效成分股总数 × 100%
```

板块涨幅和涨停占比对外统一四舍五入保留2位小数。

### 5. 板块日线

```text
当年首个交易日：open = 1000
其他交易日：open = 上一交易日 close
close = open × (1 + 当日板块涨幅 / 100)
```

- 板块日线只保存文档明确的数据：交易日、开盘值、收盘值、板块涨幅、成交额和计算时成分股数量。
- 不自行虚构板块最高价、最低价、成交量等字段。
- 股票日行情15:02完整入库后，再从数据库读取原始股票行情计算并保存当天板块日线；不再次请求腾讯。
- 当前没有历史板块成分关系。若必须从2026年年初生成板块日线，只能使用当前成分股回算，并将这批数据标记为 `PARTIAL`，它会存在成分股前视偏差。

## 推荐同步流程

### 板块和成分股

1. 交易日09:10股票清单同步完成。
2. 09:15每天只请求一次板块接口。
3. 校验 `code=200`、`data`非空、板块名非空、股票代码为6位字符串。
4. 对同一板块的股票代码去重，整批校验成功后事务保存。
5. 本次完整响应中未出现的旧关系标记为失效，禁止接口失败时误删旧数据。

### 板块日线

1. 15:02股票日行情全量同步成功。
2. 确认股票行情数量完整。
3. 一次性分批读取当天股票涨幅和成交额原始数据。
4. Service按板块成分关系计算涨幅、成交额、开盘值和收盘值。
5. 批量幂等保存板块日线；任一关键步骤失败时不写入残缺结果。

### 当天最新查询

1. 校验当天为交易日且时间不早于09:30；午休和收盘后允许查询最近状态。
2. 获取60秒全市场实时行情快照。
3. 把行情按股票代码构建Map。
4. 遍历板块成分关系，计算每个板块的5个响应字段。
5. 全量排序后分页返回。

## 推荐接口

```text
GET /api/plate/limitUpStatistics?pageNum=1&pageSize=20
```

建议默认每页20条、最大100条。指定接口响应体较大且板块数量明显不适合一次全部返回，因此必须分页。

单条记录只返回文档明确的5个字段：

```json
{
  "plateName": "长三角一体化-概",
  "totalStockCount": 128,
  "plateChangePercent": 1.26,
  "limitUpStockCount": 4,
  "limitUpRatio": 3.13
}
```

推荐返回全部有效板块，包括涨停个股数为0的板块；排序使用涨停个股数倒序、涨停占比倒序、板块涨幅倒序、板块名升序。

## 最小表设计

### `stock_plate`

保存板块名称、数据来源、最近同步交易日和有效状态；同一数据来源下板块名称唯一。

### `stock_plate_member`

保存板块与股票代码的多对多关系、最近同步交易日和有效状态；`(plate_id, stock_code)` 唯一。

### `stock_plate_daily_quote`

保存板块交易日、open、close、板块涨幅、成交额、成分股数量、数据来源和数据状态；`(plate_id, trade_date)` 唯一。

所有SQL只读取和保存原始数据，不在SQL中使用 `AVG`、`SUM`、`GROUP BY` 完成板块业务计算。

## 代码职责建议

- 新建 `controller/plate` 和 `service/plate/impl`，不建立新的顶层领域包。
- 板块外部接口解析放在独立数据源Service实现中。
- 板块涨幅、指数值、涨停数量和占比放在可单元测试的计算组件中。
- 将股票预警Service中的60秒全市场快照下沉为 `stockdailyquote` 模块的共享Service，供功能3和功能5复用，避免两个接口各自请求全市场行情。
- 定时任务只负责编排，板块同步和计算细节放入Service或Face。

## 测试重点

- 板块JSON正常、空响应、错误状态、非法股票代码和同板块重复代码。
- 一只股票属于多个板块时，各板块独立统计且单板块内不重复计数。
- ST股票计入总个数但不计入涨停数。
- 卖一量为0、非0和NULL三种边界。
- 板块涨幅、涨停占比和2位小数舍入口径。
- 当年首个交易日open为1000，后续open承接前收，跨年重新从1000开始。
- 股票行情不完整时不生成板块结果。
- 非交易日、开盘前、午休和收盘后查询边界。
- 板块成分同步幂等、失效关系处理和板块日线唯一约束。

## 已采用口径

1. 板块范围只使用指定接口返回的同花顺三级概念板块。
2. 涨停个股复用功能3的“卖一量为0”等条件。
3. 首次初始化使用当前成分股回算当年板块日线，并标记为 `PARTIAL`。
4. 返回全部有效板块，并按“涨停数、涨停占比、板块涨幅、板块名”排序分页。
