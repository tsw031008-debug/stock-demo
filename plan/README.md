# 项目进度文档说明

`plan` 目录用于记录项目当前状态和每次功能推进情况，方便快速了解已完成内容、验证结果和后续安排。

## 本机需求文档

```text
C:\Users\17\Desktop\产品组-试用期2.docx
```

后续分析试用期需求时，以该文档为准。

## 文档组成

- `PROJECT_STATUS.md`：项目当前进度总览，每次推进后同步更新。
- `YYYY-MM-DD-NNN-topic.md`：单次推进记录，创建后保留，不覆盖历史记录。

## 命名规则

推进记录统一使用以下格式：

```text
YYYY-MM-DD-NNN-topic.md
```

示例：

```text
2026-08-20-001-project-baseline.md
2026-08-21-001-stock-basic-info.md
```

- 日期使用实际完成或推进日期。
- 序号从当天 `001` 开始递增。
- `topic` 使用简短英文小写单词和连字符，表达本次主题。

## 更新要求

每次实现功能、调整架构、修改公共约定或解决重要问题后：

1. 新增一份推进记录。
2. 同步更新 `PROJECT_STATUS.md`。
3. 记录实际完成内容、涉及文件、验证结果、遗留问题和下一步。
4. 尚未完成或未经验证的内容必须明确标记，不能写成已完成。
5. 不在文档中记录密码、Token、数据库连接串等敏感信息。

以下情况不创建推进记录：

- 文字修正、格式整理和无行为变化的重命名。
- `AGENTS.md` 等开发规范的调整。
- `plan` 目录内进度文档自身的整理和修正。
- 只讨论方案但未产生实际项目成果。
